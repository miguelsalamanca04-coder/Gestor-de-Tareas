Qué es esto
-----------
El Gestor de Tareas al cierre del Sub-bloque A. Sirve para COMPARAR con tu
propio trabajo de la Sesión 26 (el punto de partida es el checkpoint de la
Sesión 25). Intenta construirlo tú primero.

Lo nuevo de la Sesión 26
-------------------------
  sw-propio.js       Service Worker escrito a mano (push, clic en la
                     notificación, Background Sync). Workbox solo le inyecta la
                     lista de precaché (InjectManifest).
  sw.js              GENERADO a partir de sw-propio.js — no se edita.
  lib/               Workbox copiado en local (npx workbox-cli copyLibraries lib)
  notificaciones.js  permiso, notificación local, suscripción push
  sync.js            bandeja de salida (outbox) + registro de Background Sync
  db.js              versión 2 de la base: agrega el almacén "outbox"
  servidor/          mini servidor Node: archivos + push + recibe tareas

Cómo ejecutarlo
----------------
  1. cd servidor
  2. npm install                 (instala web-push)
  3. node server.js              → http://localhost:3000
  La primera vez se crean las claves VAPID (servidor/claves-vapid.json).
  NO subas ese archivo a Git: la clave privada identifica a TU servidor.

Cada vez que cambies sw-propio.js o un archivo precacheado:
  (desde la carpeta del Gestor, no desde servidor/)
  npx workbox-cli injectManifest workbox-config.js

Qué probar
-----------
  - "🔔 Activar avisos" → notificación local.
  - DevTools → Network → Offline, agrega una tarea: queda «pendiente».
    Vuelve a Online (o DevTools → Application → Background Sync → Sync).
  - "📡 Suscribir a push" + "✉ Enviar push de prueba". El push real depende
    del servicio de push de tu navegador (Chrome usa los servidores de
    Google): necesita acceso a Internet y un navegador con push. En
    Application → Service Workers puedes pulsar «Push» para simularlo.

Importante: es código de enseñanza. El servidor no tiene autenticación, ni base
de datos real, ni HTTPS. No lo publiques tal cual.
